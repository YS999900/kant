## 1. WHERE — 복합 조건 조회

`WHERE`는 특정 조건을 만족하는 데이터만 조회하는 명령어이다.

여러 조건을 조합할 때 `AND`, `OR`를 사용할 수 있다.

```sql
SELECT course_name, level, start_time
FROM courses
WHERE sport_id = 1
  AND (level = '초급' OR start_time < '09:00');
```

| 문법 | 의미 |
|---|---|
| `WHERE` | 조건 지정 |
| `AND` | 모든 조건을 만족 |
| `OR` | 하나 이상의 조건을 만족 |
| `( )` | 조건을 묶어 우선순위 지정 |

**핵심:** `AND`와 `OR`를 함께 사용할 때 괄호를 사용하면 조건의 의미를 명확하게 표현할 수 있다.

## 2. CASE WHEN — 조건별 데이터 분류

`CASE WHEN`은 조건에 따라 서로 다른 값을 반환한다.

```sql
SELECT
    name,
    birth_year,
    CASE
        WHEN birth_year <= 1960 THEN '할인'
        WHEN birth_year >= 2000 THEN '청소년'
        ELSE '일반'
    END AS 요금구분
FROM members
ORDER BY birth_year, name
LIMIT 10;
```

### 주요 문법

| 문법 | 역할 |
|---|---|
| `CASE` | 조건문 시작 |
| `WHEN` | 조건 설정 |
| `THEN` | 조건 만족 시 반환값 |
| `ELSE` | 모든 조건을 만족하지 않을 때 반환값 |
| `END` | 조건문 종료 |
| `AS` | 결과 컬럼에 별칭 지정 |

조건은 위에서 아래로 평가하며, 처음 만족하는 조건의 값을 반환한다.

## 3. ORDER BY — 데이터 정렬

조회 결과를 특정 컬럼 기준으로 정렬한다.

```sql
SELECT course_name, fee
FROM courses
WHERE fee >= 80000
ORDER BY fee DESC, course_name;
```

- `ASC`: 오름차순 (기본값)
- `DESC`: 내림차순
- 여러 컬럼을 지정하면 앞의 컬럼부터 정렬한다.

위 코드는 수강료가 80,000원 이상인 강좌를 조회하고, 수강료가 높은 순서대로 정렬한다. 수강료가 같다면 강좌명 오름차순으로 정렬한다.

### NULL이 포함된 데이터 정렬

```sql
SELECT name, email
FROM members
ORDER BY email DESC, name;
```

PostgreSQL에서는 별도 지정하지 않으면 `DESC` 정렬 시 `NULL`이 먼저 표시된다.

`NULLS FIRST`, `NULLS LAST`로 위치를 지정할 수도 있다.

## 4. 집계 함수 — 데이터 계산

집계 함수는 여러 행의 데이터를 하나의 결과로 계산할 때 사용한다.

```sql
SELECT
    COUNT(*)             AS 강좌수,
    MIN(fee)             AS 최저수강료,
    MAX(fee)             AS 최고수강료,
    SUM(capacity)        AS 전체정원,
    ROUND(AVG(fee), 2)   AS 평균수강료
FROM courses;
```

### 주요 집계 함수

| 함수 | 기능 |
|---|---|
| `COUNT()` | 데이터 개수 계산 |
| `MIN()` | 최솟값 |
| `MAX()` | 최댓값 |
| `SUM()` | 합계 |
| `AVG()` | 평균 |
| `ROUND()` | 지정한 소수점 자리까지 반올림 |

### COUNT(*)와 COUNT(컬럼)의 차이

```sql
SELECT
    COUNT(*)               AS 회원수,
    COUNT(email)           AS 이메일있음,
    COUNT(phone)           AS 전화번호있음,
    COUNT(DISTINCT region) AS 거주지
FROM members;
```

- `COUNT(*)`: 모든 행의 개수
- `COUNT(email)`: 이메일이 NULL이 아닌 행의 개수
- `COUNT(DISTINCT region)`: 중복을 제거한 NULL이 아닌 거주지의 개수

**핵심:** `COUNT(컬럼)`은 NULL 값을 제외한다.

## 5. GROUP BY — 그룹별 데이터 집계

`GROUP BY`는 특정 컬럼의 값이 같은 데이터끼리 묶어서 집계한다.

### 월별 수강 신청 건수 및 매출

```sql
SELECT
    enroll_month    AS 신청월,
    COUNT(*)        AS 신청건수,
    SUM(pay_amount) AS 매출
FROM enrollments
GROUP BY enroll_month
ORDER BY enroll_month;
```

### 월별·상태별 신청 건수

```sql
SELECT
    enroll_month,
    status,
    COUNT(*) AS 건수
FROM enrollments
GROUP BY enroll_month, status
ORDER BY enroll_month, status;
```

여러 컬럼을 `GROUP BY`에 작성하면 해당 컬럼들의 조합을 기준으로 그룹을 생성한다.

### GROUP BY 주요 규칙

집계 함수로 감싸지 않은 일반 컬럼을 `SELECT`에서 조회한다면 일반적으로 해당 컬럼을 `GROUP BY`에 포함해야 한다.

## 6. HAVING — 그룹별 조건 필터링

`HAVING`은 `GROUP BY`로 집계한 결과에 조건을 적용한다.

### 누적 신청 건수 조회

```sql
SELECT
    course_id,
    COUNT(*) AS 누적신청
FROM enrollments
WHERE status <> '취소'
GROUP BY course_id
HAVING COUNT(*) >= 18
ORDER BY 누적신청 DESC, course_id;
```

- `WHERE`: 취소된 신청 데이터를 제외
- `GROUP BY`: 강좌별로 그룹화
- `HAVING`: 신청 건수가 18건 이상인 강좌만 선택
- `ORDER BY`: 누적 신청 건수가 많은 순서로 정렬

### 거주지별 회원 수 조회

```sql
SELECT
    region,
    COUNT(*) AS 회원수
FROM members
GROUP BY region
HAVING COUNT(*) >= 10
ORDER BY 회원수 DESC;
```

거주지별로 회원 수를 계산하고, 회원이 10명 이상인 지역만 조회한다.

### WHERE와 HAVING 비교

| 구분 | WHERE | HAVING |
|---|---|---|
| 대상 | 개별 행 | 그룹별 집계 결과 |
| 적용 시점 | 그룹화 이전 | 그룹화 이후 |
| 예시 | `status <> '취소'` | `COUNT(*) >= 18` |

## 7. UNION / UNION ALL — 조회 결과 결합

여러 `SELECT`문의 결과를 하나로 결합할 때 사용한다.

### UNION — 중복 제거

```sql
SELECT member_id
FROM enrollments
WHERE course_id = 4 AND enroll_month = '2026-09'

UNION

SELECT member_id
FROM enrollments
WHERE course_id = 4 AND enroll_month = '2026-10'

UNION

SELECT member_id
FROM enrollments
WHERE course_id = 4 AND enroll_month = '2026-11'

ORDER BY member_id;
```

9월, 10월, 11월에 특정 강좌를 신청한 회원을 결합하고 중복 회원 번호를 제거한다.

### UNION ALL — 중복 유지

```sql
SELECT '강사' AS 구분, name, phone
FROM instructors
WHERE sport_id = 4

UNION ALL

SELECT '회원' AS 구분, name, phone
FROM members
WHERE region = '영등포구';
```

강사 조회 결과와 회원 조회 결과를 하나로 연결한다.

| 구분 | UNION | UNION ALL |
|---|---|---|
| 중복 행 제거 | O | X |
| 중복 행 유지 | X | O |
| 일반적인 처리 비용 | 중복 제거 작업 필요 | 상대적으로 단순 |

두 SELECT문의 결과 컬럼 수가 같아야 하며, 대응하는 컬럼의 자료형도 호환되어야 한다.

## 8. JOIN — 여러 테이블 연결

`JOIN`은 테이블 간 관계를 이용하여 여러 테이블의 데이터를 한 번에 조회하는 기능이다.

### LEFT JOIN

```sql
SELECT
    e.member_id,
    m.name,
    c.course_name,
    e.enroll_month,
    e.status
FROM enrollments e
LEFT JOIN members m
    ON e.member_id = m.member_id
LEFT JOIN courses c
    ON e.course_id = c.course_id
WHERE e.course_id = 1
  AND e.enroll_month = '2026-11'
ORDER BY m.name;
```

`enrollments`를 기준으로 회원 및 강좌 정보를 연결한다.

### 테이블 별칭

| 별칭 | 실제 테이블 |
|---|---|
| `e` | enrollments |
| `m` | members |
| `c` | courses |

`e.member_id`처럼 작성하면 어느 테이블의 컬럼인지 명확하게 구분할 수 있다.

### FULL OUTER JOIN

```sql
SELECT
    c.course_id,
    c.course_name,
    i.name AS 강사
FROM courses c
FULL OUTER JOIN instructors i
    ON c.instructor_id = i.instructor_id
ORDER BY c.course_id;
```

`FULL OUTER JOIN`은 두 테이블의 모든 행을 대상으로 연결한다.

- 일치하는 데이터가 있으면 연결
- 왼쪽 테이블에만 있는 행도 포함
- 오른쪽 테이블에만 있는 행도 포함
- 연결되는 값이 없으면 반대쪽 컬럼에는 NULL이 표시됨

### JOIN 종류 비교

| 종류 | 조회 대상 |
|---|---|
| `INNER JOIN` | 양쪽 조건이 일치하는 행 |
| `LEFT JOIN` | 왼쪽 테이블의 모든 행 |
| `RIGHT JOIN` | 오른쪽 테이블의 모든 행 |
| `FULL OUTER JOIN` | 양쪽 테이블의 모든 행 |

## 9. 서브쿼리 — Subquery

서브쿼리는 SQL문 내부에 작성하는 또 다른 SQL문이다.

### WHERE 서브쿼리

전체 강좌의 평균 수강료보다 비싼 강좌를 조회한다.

```sql
SELECT course_name, fee
FROM courses
WHERE fee > (
    SELECT AVG(fee)
    FROM courses
)
ORDER BY fee DESC, course_name;
```

내부 쿼리에서 평균 수강료를 계산한 뒤, 외부 쿼리에서 평균보다 높은 강좌를 조회한다.

## 10. FROM 서브쿼리 — Inline View

`FROM`절에 서브쿼리를 작성하여 임시 조회 결과를 테이블처럼 사용한다.

```sql
SELECT
    paid.member_id  AS 회원번호,
    m.name          AS 회원명,
    paid.total_paid AS 매출액
FROM
(
    SELECT
        member_id,
        SUM(pay_amount) AS total_paid
    FROM enrollments
    GROUP BY member_id
) AS paid
LEFT JOIN members m
    ON paid.member_id = m.member_id
WHERE paid.total_paid >= 400000
ORDER BY paid.total_paid DESC, paid.member_id;
```

### 실행 개념

1. 서브쿼리에서 회원별 결제금액을 합산한다.
2. 계산한 결과에 `paid`라는 별칭을 지정한다.
3. `members` 테이블과 JOIN하여 회원 이름을 가져온다.
4. 총결제금액이 400,000원 이상인 회원만 조회한다.
5. 매출액이 높은 순서대로 정렬한다.

**핵심:** 복잡한 집계 결과를 하나의 임시 테이블처럼 활용할 수 있다.

## 11. SELECT 서브쿼리 — Scalar Subquery

스칼라 서브쿼리는 하나의 값을 반환하는 서브쿼리이다.

```sql
SELECT
    course_name,
    fee,
    ROUND(
        (SELECT AVG(fee) FROM courses), 2
    ) AS 전체평균,
    fee - ROUND(
        (SELECT AVG(fee) FROM courses), 2
    ) AS 평균과차이
FROM courses;
```

각 강좌의 수강료와 전체 평균 수강료, 평균과의 차이를 함께 조회한다.

### 서브쿼리 위치 비교

| 위치 | 활용 방법 |
|---|---|
| `WHERE` | 다른 조회 결과를 조건으로 사용 |
| `FROM` | 조회 결과를 임시 테이블처럼 사용 |
| `SELECT` | 조회 결과에 계산된 값 추가 |

## 12. 실습 오류 및 수정 사항

오늘 작성한 코드 중 일부에서 오타와 문법 오류가 있었다.

| 오류 | 원인 | 수정 |
|---|---|---|
| `course_namem level` | 컬럼명 오타 및 쉼표 누락 | `course_name, level` |
| `lebel` | 컬럼명 오타 | `level` |
| `'초급' start_time` | 조건 연결 연산자 누락 | `OR` 또는 `AND` 추가 |
| `enroll_month, AS` | 불필요한 쉼표 | `enroll_month AS` |
| `FROM enrollmonths` | 테이블 이름 불일치 | `FROM enrollments` |
| `ORDER BY ... member_id` | JOIN 시 컬럼이 모호할 수 있음 | `paid.member_id`로 명시 |

### 추가 확인사항

- 첫 번째 조건 조회문의 `AND`와 `OR`는 실제 조회 의도에 맞춰 선택해야 한다.
- `CASE WHEN`의 청소년·할인 구분은 학습용 출생 연도 기준이다.
- 수강 신청 내역의 `MAX(pay_amount)`는 최대 개별 결제금액이며, 강좌별 최고 누적 매출과는 다른 개념이다.
- `FULL OUTER JOIN`은 강사가 배정되지 않은 강좌와 강좌가 배정되지 않은 강사를 모두 포함할 수 있다.
