## 1. PostgreSQL 데이터베이스 및 테이블 설계

생활체육 회원관리 시스템을 구성하기 위해 여러 테이블을 생성하고 외래키로 연결했다.

```sql
CREATE DATABASE sportscenter;
```

### 주요 테이블

| 테이블 | 역할 | 기본키 |
|---|---|---|
| `members` | 회원 정보 관리 | `member_id` |
| `sports` | 운동 종목 관리 | `sports_id` |
| `courses` | 개설 강좌 관리 | `course_id` |
| `lockers` | 회원별 사물함 관리 | `locker_no` |
| `enrollments` | 회원 수강 신청 관리 | 복합 기본키 |
| `instructors` | 강사 정보 관리 | `instructor_id` |

### 기본키와 외래키

- **PRIMARY KEY(PK)**: 테이블의 각 데이터를 고유하게 식별하는 키
- **FOREIGN KEY(FK)**: 다른 테이블의 데이터를 참조하여 테이블 간 관계를 설정하는 키

```sql
sports_id INT NOT NULL REFERENCES sports(sports_id)
```

`courses` 테이블에서 `sports` 테이블의 종목 ID를 참조하도록 설정했다.

외래키가 설정된 컬럼에는 참조 대상 테이블에 존재하지 않는 값을 입력할 수 없다.

## 2. ON DELETE CASCADE — 참조 데이터 자동 삭제

회원과 사물함의 관계를 설정하면서 `ON DELETE CASCADE`를 학습했다.

### 사물함 테이블

```sql
CREATE TABLE lockers
(
    locker_no  INT PRIMARY KEY,
    member_id  INT NOT NULL UNIQUE
               REFERENCES members(member_id)
               ON DELETE CASCADE,
    asign_date DATE NOT NULL
);
```

### 주요 제약조건

| 문법 | 의미 |
|---|---|
| `PRIMARY KEY` | 사물함 번호 중복 방지 |
| `NOT NULL` | 회원 번호 필수 입력 |
| `UNIQUE` | 회원 한 명당 사물함 최대 1개 |
| `REFERENCES` | 회원 테이블의 기본키 참조 |
| `ON DELETE CASCADE` | 회원 삭제 시 연결된 사물함 정보 자동 삭제 |

### 삭제 동작 실습

```sql
INSERT INTO members (name, gender, birth_year, join_date)
VALUES ('임시회원', 'M', 2000, '2026-11-01');
```

임시 회원의 사물함을 배정한 후, 회원을 삭제하는 실습을 진행했다.

```sql
DELETE FROM members
WHERE member_id = 3;
```

```sql
SELECT * FROM lockers;
```

**핵심:** `ON DELETE CASCADE`가 설정되어 있으면 부모 테이블의 데이터가 삭제될 때 이를 참조하는 자식 테이블의 데이터도 함께 삭제된다.

단, 실습에서 지정한 `member_id = 3`이 실제 임시 회원의 번호인지는 먼저 확인해야 한다.

## 3. 복합 기본키 — Composite Primary Key

수강 신청 정보를 관리하는 `enrollments` 테이블에서 복합 기본키를 학습했다.

```sql
CREATE TABLE enrollments
(
    member_id    INT NOT NULL REFERENCES members(member_id),
    course_id    INT NOT NULL REFERENCES courses(course_id),
    enroll_month CHAR(7) NOT NULL,
    status       VARCHAR(10) NOT NULL,
    pay_amount   NUMERIC(10,2) NOT NULL CHECK (pay_amount >= 0),

    PRIMARY KEY (member_id, course_id, enroll_month)
);
```

### 복합 기본키란?

두 개 이상의 컬럼을 묶어 하나의 기본키로 사용하는 방법이다.

```sql
PRIMARY KEY (member_id, course_id, enroll_month)
```

| member_id | course_id | enroll_month | 등록 가능 여부 |
|---|---|---|---|
| 1 | 1 | 2026-11 | 가능 |
| 1 | 2 | 2026-11 | 가능 |
| 1 | 1 | 2026-12 | 가능 |
| 1 | 1 | 2026-11 | 중복 불가 |

회원 번호, 강좌 번호, 수강 월이 모두 같은 데이터는 중복 등록할 수 없다.

### NUMERIC 자료형

```sql
pay_amount NUMERIC(10,2) NOT NULL CHECK (pay_amount >= 0)
```

- `NUMERIC(10,2)`: 전체 최대 10자리 중 소수점 이하 2자리까지 저장
- `NOT NULL`: 값이 없는 상태 방지
- `CHECK (pay_amount >= 0)`: 음수 금액 입력 방지

금액처럼 정확한 수치 저장이 필요한 경우 활용할 수 있다.

## 4. ALTER TABLE — 기존 테이블 수정

`ALTER TABLE`은 이미 생성된 테이블의 구조를 변경하는 명령어이다.

### 강사 컬럼 추가

```sql
ALTER TABLE courses
ADD COLUMN instructor_id INT REFERENCES instructors(instructor_id);
```

기존 `courses` 테이블에 강사 번호 컬럼을 추가하고, `instructors` 테이블의 기본키를 참조하도록 설정한다.

### 주요 문법

| 명령어 | 기능 |
|---|---|
| `ALTER TABLE` | 기존 테이블 구조 변경 |
| `ADD COLUMN` | 새로운 컬럼 추가 |
| `DROP COLUMN` | 기존 컬럼 삭제 |
| `ALTER COLUMN` | 컬럼 속성 변경 |
| `RENAME COLUMN` | 컬럼 이름 변경 |

테이블을 새로 만들지 않고도 컬럼과 제약조건을 추가하거나 수정할 수 있다.

## 5. DROP TABLE IF EXISTS — 테이블 삭제

```sql
DROP TABLE IF EXISTS lockers;
```

- `DROP TABLE`: 테이블 자체 삭제
- `IF EXISTS`: 테이블이 있을 때만 삭제하도록 처리

`DROP TABLE`은 테이블의 구조와 데이터를 모두 제거한다.

### DELETE와 DROP의 차이

| 명령어 | 기능 |
|---|---|
| `DELETE FROM` | 테이블의 행 삭제 |
| `DROP TABLE` | 테이블 자체 삭제 |
| `DROP DATABASE` | 데이터베이스 자체 삭제 |

**주의:** 다른 테이블에서 외래키로 참조하는 테이블은 의존 관계 때문에 삭제가 제한될 수 있다.

## 6. SELECT — 데이터 조회

### 전체 데이터 조회

```sql
SELECT * FROM members;
```

`*`는 모든 컬럼을 의미한다.

### 특정 컬럼 조회 및 별칭 지정

```sql
SELECT
    course_name AS 강좌명,
    fee AS 수강료,
    fee * 3 AS "3개월 수강료"
FROM courses
LIMIT 5;
```

| 문법 | 의미 |
|---|---|
| `SELECT` | 조회할 데이터 지정 |
| `AS` | 조회 결과의 컬럼 이름 변경 |
| `fee * 3` | 수강료에 3을 곱한 계산 결과 |
| `LIMIT 5` | 최대 5개 행 조회 |

`AS`는 실제 테이블의 컬럼 이름을 변경하는 것이 아니라 조회 결과에 표시되는 이름을 지정한다.

## 7. DISTINCT — 중복 제거

```sql
SELECT DISTINCT sport_id, level
FROM courses;
```

`DISTINCT`는 조회 결과에서 중복된 행을 제거한다.

여러 컬럼을 함께 선택하면 해당 컬럼들의 **조합을 기준으로 중복 여부를 판단**한다.

예를 들어 같은 종목과 같은 난이도의 조합이 여러 번 등장해도 한 번만 출력된다.

## 8. WHERE — 조건에 맞는 데이터 조회

`WHERE`는 특정 조건을 만족하는 데이터만 조회할 때 사용한다.

### 비교 연산자

| 연산자 | 의미 |
|---|---|
| `=` | 같다 |
| `<>` | 같지 않다 |
| `>` | 초과 |
| `<` | 미만 |
| `>=` | 이상 |
| `<=` | 이하 |

### 회원 번호 조건 조회

```sql
SELECT * FROM members
WHERE member_id <= 7;
```

회원 번호가 7 이하인 회원을 조회한다.

### 지역 조건 조회

```sql
SELECT * FROM members
WHERE region = '마포구';
```

지역이 마포구인 회원만 조회한다.

## 9. IS NULL — NULL 값 조회

```sql
SELECT * FROM members
WHERE email IS NULL;
```

이메일 정보가 없는 회원을 조회한다.

### COUNT — 데이터 개수 확인

```sql
SELECT COUNT(*)
FROM members
WHERE email IS NULL;
```

이메일이 없는 회원의 수를 반환한다.

### 별칭 지정

```sql
SELECT COUNT(*) AS "E-MAIL미기재"
FROM members
WHERE email IS NULL;
```

`COUNT(*)`는 조건에 해당하는 행의 수를 계산하고 `AS`는 결과 컬럼의 이름을 지정한다.

**주의:** `NULL`은 일반적인 값이 아니므로 `= NULL`이 아닌 `IS NULL`을 사용한다.

---

## 10. BETWEEN — 범위 조건 조회

```sql
SELECT * FROM members
WHERE birth_year BETWEEN 1995 AND 2000;
```

출생 연도가 1995년부터 2000년 사이인 회원을 조회한다.

`BETWEEN`은 시작값과 끝값을 모두 포함한다.

다음 조건과 같은 의미이다.

```sql
WHERE birth_year >= 1995
  AND birth_year <= 2000;
```

---

## 11. IN — 여러 값 중 하나와 일치하는 데이터 조회

```sql
SELECT * FROM courses
WHERE course_id IN (1, 5, 10);
```

강좌 번호가 1번, 5번, 10번 중 하나인 데이터를 조회한다.

다음 조건과 같은 의미이다.

```sql
WHERE course_id = 1
   OR course_id = 5
   OR course_id = 10;
```

`IN`을 사용하면 여러 값에 대한 조건을 간결하게 작성할 수 있다.

## 12. LIKE — 문자열 패턴 검색

```sql
SELECT * FROM members
WHERE name LIKE '김%';
```

이름이 `김`으로 시작하는 회원을 조회한다.

### LIKE 와일드카드

| 기호 | 의미 |
|---|---|
| `%` | 0개 이상의 임의 문자 |
| `_` | 임의의 문자 1개 |

### 예시

```sql
WHERE name LIKE '김%';
```

김으로 시작하는 이름 조회

```sql
WHERE name LIKE '%민';
```

민으로 끝나는 이름 조회

```sql
WHERE name LIKE '%준%';
```

준이 포함된 이름 조회

## 13. SQL 오류 및 학습 내용

| 오류 및 주의사항 | 원인 | 해결 및 학습 내용 |
|---|---|---|
| 외래키 참조 오류 | 참조한 컬럼 이름이 실제 테이블과 다름 | `\d 테이블명`으로 컬럼 확인 |
| `instructor`와 `instructors` 혼동 | 테이블 이름 불일치 | 이름 통일 |
| 중복 수강 신청 | 복합 기본키의 세 컬럼 조합이 중복됨 | 기존 데이터 확인 |
| 존재하지 않는 종목 번호 | 외래키 제약조건 위반 | 실제 종목 ID 확인 |
| 임시 회원 삭제 실습 | 자동 생성된 회원 번호를 직접 가정함 | 실제 회원 ID 조회 |
| `DROP TABLE` 사용 | 테이블과 데이터가 함께 삭제됨 | 삭제 대상 및 의존 관계 확인 |

### 코드에서 추가로 확인할 부분

**① 강사 테이블 이름 통일**

```sql
CREATE TABLE instructors (...)
```

테이블을 `instructors`로 만들었다면 `INSERT INTO`와 `REFERENCES`에서도 `instructors`를 사용해야 한다.

**② 강사 컬럼 이름 확인**

```sql
sport_id INT REFERENCES sports(sports_id)
```

현재 테이블의 컬럼명과 참조 대상의 컬럼명이 반드시 같을 필요는 없다.

**③ 복합 기본키 중복**

```sql
INSERT INTO enrollments
VALUES (2, 2, '2026-10', '수료', 70000);
```

동일한 `member_id`, `course_id`, `enroll_month` 조합으로 다시 입력하면 중복 오류가 발생한다.
