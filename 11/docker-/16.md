## 1. Docker Compose — PostgreSQL 환경 구성

Docker Compose를 활용하여 생활체육 회원관리 실습용 PostgreSQL 컨테이너를 구성했다.

### compose.yaml

```yaml
name: sportscenter

services:
  db:
    container_name: sportscenter-db
    image: postgres:18
    environment:
      POSTGRES_PASSWORD: 1234
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql

volumes:
  pgdata:
```

### 주요 설정

| 항목 | 기능 |
|---|---|
| `name` | Compose 프로젝트 이름 |
| `services` | 실행할 서비스 정의 |
| `db` | PostgreSQL 서비스 이름 |
| `container_name` | 컨테이너 이름 지정 |
| `image` | 사용할 Docker 이미지 |
| `environment` | 환경변수 지정 |
| `ports` | 호스트와 컨테이너 포트 연결 |
| `volumes` | 데이터 저장 공간 연결 |

### PostgreSQL 접속

```bash
docker compose exec db psql -U postgres -d sportscenter
```

- `docker compose exec`: 실행 중인 서비스의 컨테이너에서 명령어 실행
- `db`: 서비스 이름
- `psql`: PostgreSQL 클라이언트
- `-U postgres`: 사용자 지정
- `-d sportscenter`: 접속할 데이터베이스 지정

Docker Volume을 연결하여 데이터베이스 파일을 컨테이너와 별도로 보존하도록 설정했다.

## 2. SQL 기본 개념 — DDL과 DML

SQL은 관계형 데이터베이스를 정의하고 데이터를 관리하기 위한 언어이다.

| 구분 | 의미 | 주요 명령어 |
|---|---|---|
| DDL | Data Definition Language | `CREATE`, `ALTER`, `DROP` |
| DML | Data Manipulation Language | `INSERT`, `SELECT`, `UPDATE`, `DELETE` |

### DDL — 데이터 정의어

```sql
CREATE DATABASE sportscenter;
```

데이터베이스를 생성한다.

```sql
CREATE TABLE members (
    member_id SERIAL PRIMARY KEY,
    name VARCHAR(30) NOT NULL
);
```

테이블의 컬럼과 자료형, 제약조건을 정의한다.

### DML — 데이터 조작어

```sql
INSERT INTO members (name)
VALUES ('김하늘');
```

위 코드는 `INSERT INTO`의 문법을 설명하기 위한 일부 예시이다. 실제 `members` 테이블에는 다른 `NOT NULL` 컬럼도 있으므로 필수 값을 모두 입력해야 한다.

**핵심 차이**

- DDL: 데이터베이스와 테이블의 구조를 정의하거나 변경
- DML: 테이블에 저장된 데이터를 조회하거나 추가·수정·삭제

## 3. members — 회원 테이블

회원의 기본 정보를 저장하는 테이블을 생성했다.

```sql
CREATE TABLE members
(
    member_id   SERIAL      PRIMARY KEY,
    name        VARCHAR(30) NOT NULL,
    gender      CHAR(1)     NOT NULL,
    birth_year  SMALLINT    NOT NULL,
    phone       VARCHAR(20),
    email       VARCHAR(50),
    region      VARCHAR(10),
    join_date   DATE        NOT NULL
);
```

### 자료형 및 제약조건

| 문법 | 의미 |
|---|---|
| `SERIAL` | 자동 증가 정수형 |
| `PRIMARY KEY` | 각 행을 고유하게 식별하는 기본키 |
| `VARCHAR(30)` | 최대 30자 문자열 |
| `CHAR(1)` | 고정 길이 1자 문자열 |
| `SMALLINT` | 작은 범위의 정수형 |
| `DATE` | 날짜 자료형 |
| `NOT NULL` | NULL 값 저장 금지 |

### 회원 데이터 등록

```sql
INSERT INTO members
(
    name,
    gender,
    birth_year,
    phone,
    email,
    region,
    join_date
)
VALUES
(
    '김하늘',
    'F',
    1995,
    '010-1234-5678',
    'haneul@example.com',
    '마포구',
    '2026-09-01'
);
```

### INSERT INTO 특징

- 입력할 컬럼을 지정할 수 있다.
- 컬럼 순서에 맞게 값을 작성해야 한다.
- 지정하지 않은 컬럼은 기본값이 적용되거나 NULL이 저장된다.
- `NOT NULL` 컬럼은 기본값이 없다면 반드시 값을 입력해야 한다.
- `member_id`는 `SERIAL`로 설정되어 있어 별도로 지정하지 않아도 자동으로 번호가 생성된다.

## 4. sports — 운동 종목 테이블

수영, 헬스처럼 개설할 운동 종목을 관리하는 테이블이다.

```sql
CREATE TABLE sports
(
    sports_id  SERIAL      PRIMARY KEY,
    sport_name VARCHAR(20) NOT NULL
);
```

### 운동 종목 등록

```sql
INSERT INTO sports (sport_name)
VALUES ('수영');

INSERT INTO sports (sport_name)
VALUES ('헬스');
```

### 테이블 구조

| 컬럼 | 자료형 | 설명 |
|---|---|---|
| `sports_id` | SERIAL | 종목 고유번호 |
| `sport_name` | VARCHAR(20) | 운동 종목 이름 |

종목별 고유번호를 부여하고, 이후 강좌 테이블에서 해당 번호를 참조하도록 설계했다.

## 5. courses — 개설 강좌 테이블

각 운동 종목에 속하는 실제 강좌를 관리하는 테이블이다.

```sql
CREATE TABLE courses
(
    course_id   SERIAL      PRIMARY KEY,
    sports_id   INT         NOT NULL REFERENCES sports(sports_id),
    course_name VARCHAR(30) NOT NULL,
    level       VARCHAR(10) NOT NULL,
    class_days  VARCHAR(10) NOT NULL,
    start_time  TIME        NOT NULL,
    capacity    SMALLINT    NOT NULL,
    fee         INT         NOT NULL
);
```

### 주요 컬럼

| 컬럼 | 의미 |
|---|---|
| `course_id` | 강좌 고유번호 |
| `sports_id` | 운동 종목 번호 |
| `course_name` | 강좌 이름 |
| `level` | 강좌 난이도 |
| `class_days` | 수업 요일 |
| `start_time` | 시작 시간 |
| `capacity` | 정원 |
| `fee` | 수강료 |

### 강좌 등록

```sql
INSERT INTO courses
(sports_id, course_name, level, class_days, start_time, capacity, fee)
VALUES
(1, '수영 초급 새벽반', '초급', '월수금', '06:00', 20, 70000);
```

```sql
INSERT INTO courses
(sports_id, course_name, level, class_days, start_time, capacity, fee)
VALUES
(2, '헬스 자유이용', '자유', '매일', '06:00', 50, 50000);
```

### FOREIGN KEY — 외래키

```sql
sports_id INT NOT NULL REFERENCES sports(sports_id)
```

`courses.sports_id`가 `sports.sports_id`를 참조하도록 설정했다.

**예시**

```sql
INSERT INTO courses
(sports_id, course_name, level, class_days, start_time, capacity, fee)
VALUES
(30, '헬스 자유이용', '자유', '매일', '06:00', 50, 50000);
```

`sports` 테이블에 `sports_id = 30`인 종목이 없다면 외래키 제약조건 위반 오류가 발생한다.

외래키를 이용하면 존재하지 않는 종목에 강좌가 등록되는 것을 방지할 수 있다.

## 6. lockers — 사물함 테이블

회원별 사물함 배정 정보를 저장하는 테이블이다.

```sql
CREATE TABLE lockers
(
    locker_no  INT  PRIMARY KEY,
    member_id  INT  NOT NULL UNIQUE
                   REFERENCES members(member_id)
                   ON DELETE CASCADE,
    asign_date DATE NOT NULL
);
```

### 주요 제약조건

| 문법 | 역할 |
|---|---|
| `PRIMARY KEY` | 사물함 번호 중복 방지 |
| `NOT NULL` | 회원 번호 필수 입력 |
| `UNIQUE` | 회원 번호 중복 배정 방지 |
| `REFERENCES` | 회원 테이블의 회원 번호 참조 |
| `ON DELETE CASCADE` | 회원 삭제 시 연결된 사물함 배정 정보 자동 삭제 |

### UNIQUE 제약조건

```sql
member_id INT NOT NULL UNIQUE
```

같은 회원 번호를 사물함 테이블에 두 번 등록할 수 없도록 제한한다.

```sql
INSERT INTO lockers
VALUES (101, 1, '2026-11-01');
```

이후 같은 회원 번호로 다시 등록하면:

```sql
INSERT INTO lockers
VALUES (102, 1, '2026-11-01');
```

다음과 같은 오류가 발생한다.

```text
ERROR: duplicate key value violates unique constraint
DETAIL: Key (member_id)=(1) already exists.
```

이는 회원 1명에게 사물함을 최대 1개만 배정하도록 설정했기 때문이다.

### ON DELETE CASCADE

```sql
REFERENCES members(member_id) ON DELETE CASCADE
```

회원 테이블에서 특정 회원이 삭제되면 해당 회원과 연결된 사물함 배정 정보도 자동으로 삭제된다.

**핵심:** 회원 정보와 사물함 배정 정보 사이의 참조 관계를 유지하는 기능이다.

## 7. 테이블 간 관계

오늘 실습한 테이블은 다음과 같이 연결된다.

```text
sports (운동 종목)
  │
  └── courses (개설 강좌)
          1:N 관계


members (회원)
  │
  └── lockers (사물함)
          1:0..1 관계
```

### 관계 정리

| 관계 | 설명 |
|---|---|
| sports → courses | 하나의 종목에 여러 강좌 등록 가능 |
| members → lockers | 회원 한 명당 사물함 최대 1개 배정 가능 |

### 1:N 관계

하나의 운동 종목에 여러 강좌가 연결될 수 있다.

예를 들어 수영이라는 종목에 초급반, 중급반, 고급반을 개설할 수 있다.

### 1:0..1 관계

회원 한 명에게 사물함이 없거나 하나만 배정될 수 있다.

`lockers.member_id`에 `UNIQUE`를 설정했기 때문에 동일 회원이 여러 사물함을 배정받을 수 없다.

단, 현재 설계에는 모든 회원이 반드시 사물함을 사용해야 한다는 제약조건은 없다.

## 8. SQL 오류 및 수정 사항

| 오류 | 원인 | 해결 |
|---|---|---|
| `column does not exist` | 존재하지 않는 컬럼 이름 사용 | 테이블 구조 및 컬럼명 확인 |
| `join_data` | 가입일 컬럼 이름 오타 | `join_date`로 수정 |
| `nenber_id` | 회원 번호 컬럼 이름 오타 | `member_id`로 수정 |
| `relation "sports" does not exist` | 테이블 이름을 `sportscenter`로 생성 | `sports`로 생성 또는 이름 수정 |
| 외래키 참조 오류 | 참조하는 컬럼이 존재하지 않음 | 참조 대상 컬럼 확인 |
| 존재하지 않는 `sports_id` 입력 | 외래키 제약조건 위반 | 실제 존재하는 종목 번호 사용 |
| `duplicate key value` | UNIQUE 컬럼에 중복 값 입력 | 다른 회원 번호 사용 또는 기존 데이터 수정 |

### ALTER TABLE — 컬럼 이름 수정

```sql
ALTER TABLE members
RENAME COLUMN join_data TO join_date;
```

```sql
ALTER TABLE members
RENAME COLUMN nenber_id TO member_id;
```

`ALTER TABLE`을 사용하면 테이블을 삭제하지 않고 기존 컬럼 이름을 변경할 수 있다.

### 테이블 구조 확인

```sql
\d members
```

테이블의 컬럼 이름, 자료형, 제약조건을 확인한다.

**기억할 점**

- SQL 파일을 수정하는 것만으로 이미 생성된 테이블 구조가 변경되지는 않는다.
- 실제 데이터베이스 구조를 변경하려면 `ALTER TABLE`을 실행해야 한다.
- 외래키를 설정하려면 참조 대상 컬럼이 존재하고 기본키 또는 적절한 고유 제약조건을 갖춰야 한다.
- `UNIQUE`는 중복 값을 허용하지 않으므로 데이터를 추가하기 전에 기존 데이터를 확인해야 한다.
