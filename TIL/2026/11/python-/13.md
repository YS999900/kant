## 1. Docker CLI 명령어

### PostgreSQL 컨테이너 실행

```bash
docker run -d --name my-pg \
  -e POSTGRES_PASSWORD=admin1234 \
  -p 5432:5432 \
  postgres:18
```

| 옵션 | 기능 |
|---|---|
| `docker run` | 컨테이너 생성 및 실행 |
| `-d` | 백그라운드 실행 |
| `--name` | 컨테이너 이름 지정 |
| `-e` | 환경변수 설정 |
| `POSTGRES_PASSWORD` | PostgreSQL 초기 관리자 비밀번호 |
| `-p 5432:5432` | 호스트와 컨테이너 포트 연결 |
| `postgres:18` | PostgreSQL 18 이미지 |

### 컨테이너 목록 확인

```bash
docker ps       # 실행 중인 컨테이너
docker ps -a    # 중지된 컨테이너 포함 전체 조회
```

### PostgreSQL 접속

```bash
docker exec -it my-pg psql -U postgres -d kant_shop
```

| 옵션 | 기능 |
|---|---|
| `docker exec` | 실행 중인 컨테이너에서 명령어 실행 |
| `-it` | 대화형 터미널 사용 |
| `my-pg` | 컨테이너 이름 |
| `psql` | PostgreSQL 클라이언트 |
| `-U postgres` | postgres 사용자로 접속 |
| `-d kant_shop` | kant_shop 데이터베이스 지정 |

## 2. 외부 SQL 파일 실행

로컬 PC에서 작성한 SQL 파일을 Docker 컨테이너의 PostgreSQL에서 실행하는 방법을 학습했다.

### 방법 1. 컨테이너에 파일 복사 후 실행

```bash
docker cp kant_shop.sql my-pg:/tmp/kant_shop.sql
```

- `docker cp`: 호스트와 컨테이너 사이에 파일 복사
- `kant_shop.sql`: 로컬 SQL 파일
- `my-pg:/tmp/kant_shop.sql`: 컨테이너 내부 저장 경로

복사한 파일 실행:

```bash
docker exec -it my-pg psql -U postgres -d postgres -f /tmp/kant_shop.sql
```

`-f`는 지정한 SQL 파일의 내용을 실행하는 옵션이다.

### 방법 2. 리다이렉션을 이용한 직접 실행

```bash
docker exec -i my-pg psql -U postgres -d postgres < kant_shop.sql
```

| 문법 | 기능 |
|---|---|
| `-i` | 표준 입력 유지 |
| `<` | 파일 내용을 명령어의 표준 입력으로 전달 |
| `kant_shop.sql` | 실행할 로컬 SQL 파일 |

**두 방법의 차이**

- 방법 1: SQL 파일을 컨테이너에 복사한 후 실행
- 방법 2: 로컬 SQL 파일을 컨테이너 내부 PostgreSQL에 직접 전달

별도의 파일 복사가 필요하지 않은 두 번째 방법이 간단하다.

**주의:** 실습 SQL 파일에 `DROP DATABASE kant_shop;`이 있으므로 `kant_shop`이 아닌 `postgres` 데이터베이스에 접속한 상태로 실행해야 한다. 기존 데이터베이스가 삭제될 수 있으므로 재실행 시 주의한다.

## 3. Docker Volume — 데이터 영구 저장

Docker Volume은 컨테이너와 별도로 데이터를 보존하는 저장 공간이다.

### Volume이 필요한 이유

일반적으로 컨테이너 내부에만 저장한 데이터는 컨테이너를 삭제하면 함께 사라진다.

Volume을 사용하면 컨테이너를 삭제하고 새로 생성해도 저장된 데이터를 다시 연결하여 사용할 수 있다.

```text
PostgreSQL 컨테이너
        ↓
Docker Volume (pgdata)
        ↓
데이터 저장
        ↓
컨테이너 삭제 및 재생성
        ↓
동일 Volume 연결
        ↓
기존 데이터 재사용
```

### Volume 관리 명령어

| 명령어 | 기능 |
|---|---|
| `docker volume ls` | 볼륨 목록 조회 |
| `docker volume create pgdata` | 볼륨 생성 |
| `docker volume inspect pgdata` | 볼륨 상세 정보 확인 |
| `docker volume rm pgdata` | 볼륨 삭제 |

### Volume을 연결한 컨테이너 생성

```bash
docker run -d --name my-pg \
  -e POSTGRES_PASSWORD=admin1234 \
  -p 5432:5432 \
  -v pgdata:/var/lib/postgresql \
  postgres:18
```

| 문법 | 기능 |
|---|---|
| `-v` | 볼륨 연결 |
| `pgdata` | Docker Volume 이름 |
| `/var/lib/postgresql` | PostgreSQL 18의 데이터 저장용 마운트 경로 |

**핵심:** `-v 볼륨명:컨테이너경로` 형식으로 사용한다.

PostgreSQL 18 공식 이미지의 권장 볼륨 경로는 `/var/lib/postgresql`이다.

## 4. Docker Compose

Docker Compose는 여러 컨테이너의 실행 설정을 YAML 파일로 관리하는 도구이다.

긴 `docker run` 명령어를 반복해서 입력하지 않고, 설정을 파일로 작성하여 관리할 수 있다.

### compose.yaml 구조

```yaml
services:
  db:
    image: postgres:18
    container_name: kant-pg
    environment:
      POSTGRES_PASSWORD: admin1234
    ports:
      - "5433:5432"
    volumes:
      - pgdata:/var/lib/postgresql

volumes:
  pgdata:
    external: true
```

### 주요 설정

| 항목 | 기능 |
|---|---|
| `services` | 실행할 서비스 정의 |
| `db` | 서비스 이름 |
| `image` | 사용할 Docker 이미지 |
| `container_name` | 컨테이너 이름 |
| `environment` | 환경변수 설정 |
| `ports` | 포트 연결 |
| `volumes` | 데이터 저장 공간 연결 |
| `external: true` | 이미 생성된 외부 볼륨 사용 |

### 포트 연결

```yaml
ports:
  - "5433:5432"
```

- `5433`: 내 컴퓨터에서 접근하는 포트
- `5432`: PostgreSQL 컨테이너 내부 포트

즉, `localhost:5433`으로 접속하면 컨테이너의 `5432` 포트에 연결된다.

`external: true`로 설정한 경우 볼륨이 미리 존재해야 한다.

```bash
docker volume create pgdata
```

### 추가 학습할 Compose 명령어

```bash
docker compose up -d
docker compose ps
docker compose down
```

- `up -d`: 서비스를 백그라운드에서 생성 및 실행
- `ps`: Compose 서비스 컨테이너 상태 확인
- `down`: Compose로 생성한 컨테이너와 네트워크 정리

## 5. PostgreSQL 데이터베이스 생성

### 데이터베이스 생성 SQL

```sql
DROP DATABASE IF EXISTS kant_shop;

CREATE DATABASE kant_shop;
```

| 명령어 | 기능 |
|---|---|
| `DROP DATABASE` | 데이터베이스 삭제 |
| `IF EXISTS` | 데이터베이스가 있을 때만 삭제 |
| `CREATE DATABASE` | 데이터베이스 생성 |

### 데이터베이스 연결

```sql
\c kant_shop
```

`\c`는 PostgreSQL의 `psql`에서 사용하는 연결 전환 명령어이다.

**주의할 점**

현재 접속 중인 데이터베이스를 삭제할 수는 없다.

따라서 데이터베이스를 삭제하고 다시 생성하는 SQL 파일은 기본 `postgres` 데이터베이스에서 실행한 후 `\c kant_shop`으로 연결을 변경한다.

## 6. Product 테이블 생성

상품 정보를 저장하는 `product` 테이블을 생성했다.

```sql
CREATE TABLE product
(
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    price INT NOT NULL,
    stock INT NOT NULL
);
```

### SQL 문법 정리

| 문법 | 기능 |
|---|---|
| `CREATE TABLE` | 테이블 생성 |
| `SERIAL` | 자동 증가 정수형 |
| `PRIMARY KEY` | 기본키 지정 |
| `VARCHAR(100)` | 최대 100자의 가변 길이 문자열 |
| `INT` | 정수형 |
| `NOT NULL` | NULL 값 저장 불가 |

### 상품 테이블 구조

| 컬럼 | 자료형 | 설명 |
|---|---|---|
| `id` | SERIAL | 상품 번호, 자동 증가 |
| `name` | VARCHAR(100) | 상품 이름 |
| `price` | INT | 상품 가격 |
| `stock` | INT | 상품 재고 수량 |

`SERIAL PRIMARY KEY`를 사용하면 상품 번호가 자동으로 증가하며, 각 상품을 구분하는 기본키로 사용된다.

## 7. 상품 데이터 추가 및 조회

### INSERT INTO — 데이터 추가

```sql
INSERT INTO product (name, price, stock) VALUES
('무선 키보드', 35000, 120),
('게이밍 마우스', 28000, 85),
('27인치 모니터', 259000, 15),
('USB-C 허브', 19900, 200),
('노트북 거치대', 24000, 7);
```

### INSERT 문법

| 문법 | 기능 |
|---|---|
| `INSERT INTO` | 테이블에 데이터 추가 |
| `(name, price, stock)` | 값을 넣을 컬럼 지정 |
| `VALUES` | 추가할 값 지정 |
| `(...)` | 한 행의 데이터 |
| `,` | 여러 행 구분 |
| `;` | SQL 문장 종료 |

### SELECT — 데이터 조회

```sql
SELECT * FROM public.product;
```

| 문법 | 기능 |
|---|---|
| `SELECT` | 데이터 조회 |
| `*` | 모든 컬럼 선택 |
| `FROM` | 조회할 테이블 지정 |
| `public` | 스키마 이름 |
| `product` | 테이블 이름 |

### 조회 결과

| id | name | price | stock |
|---|---|---:|---:|
| 1 | 무선 키보드 | 35000 | 120 |
| 2 | 게이밍 마우스 | 28000 | 85 |
| 3 | 27인치 모니터 | 259000 | 15 |
| 4 | USB-C 허브 | 19900 | 200 |
| 5 | 노트북 거치대 | 24000 | 7 |

SQL을 이용하여 상품 5개를 추가하고 정상적으로 조회하는 과정을 학습했다.

## 8. VS Code DBCode 연결 및 조회

DBCode 확장 프로그램을 사용하여 PostgreSQL 데이터베이스에 접속하고 테이블을 조회했다.

### 연결 설정

| 항목 | 값 |
|---|---|
| Connection | kant-pg |
| Host | localhost |
| Port | 5433 |
| Username | postgres |
| Database | kant_shop |

### 테이블 조회

DBCode에서 `kant_shop` 연결을 선택한 후 다음 SQL을 실행했다.

```sql
SELECT * FROM public.product;
```

상품 5개가 정상적으로 출력되는 것을 확인했다.

### DBCode 탐색기 구조

```text
kant-pg
└── kant_shop
    └── Schemas
        └── public
            └── Tables
                └── product
```

처음에는 `product` 테이블이 DBCode 탐색기에 표시되지 않았지만, `Tables` 항목을 우클릭한 후 `Refresh`를 실행하여 해결했다.

**기억할 점**

PostgreSQL 내부 데이터는 정상인데 DBCode에 테이블이 보이지 않는다면 연결 정보, 포트, 탐색기 새로고침 상태를 확인해야 한다.

## 9. 오류 및 수정 사항

| 오류 | 원인 | 해결 |
|---|---|---|
| `database does not exist` | 데이터베이스 미생성 | `CREATE DATABASE` 실행 |
| `relation "product" does not exist` | 테이블이 없거나 검색 경로에서 찾지 못함 | 테이블 및 스키마 확인 |
| `init.sql: No such file or directory` | 실제 SQL 파일 이름 불일치 | `kant_shop.sql`로 수정 |
| `cannot drop the currently open database` | 현재 접속한 DB 삭제 시도 | `postgres` DB에서 SQL 실행 |
| DBCode에 테이블 미표시 | 탐색기 목록 갱신 필요 | `Tables → Refresh` |
| SQL을 Git Bash에 직접 입력 | PostgreSQL이 아닌 Bash에서 실행 | `psql` 또는 DBCode SQL 실행 기능 사용 |

### 실습 중 확인한 주요 사항

- SQL 파일 경로와 이름을 정확하게 확인해야 한다.
- `DROP DATABASE`는 기존 데이터를 삭제하므로 주의해야 한다.
- DB와 테이블은 서로 다른 개념이다.
- DB를 생성했다고 테이블이 자동 생성되지는 않는다.
- DBCode에 테이블이 표시되지 않더라도 실제 데이터베이스에는 존재할 수 있다.
