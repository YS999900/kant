# 1. 변수 재할당

```python
age = 20
age = 25

print(age)
```

결과:

```text
25
```

Python에서 변수는 값을 직접 담는 상자라기보다 **객체를 가리키는 이름**으로 이해하는 것이 좋다.

```text
age = 20

age
 ↓
20 객체
```

이후:

```python
age = 25
```

를 실행하면:

```text
age
 ↓
25 객체
```

처럼 `age`가 다른 객체를 가리키게 된다.

> `age = 20`을 실행할 때마다 반드시 새로운 `20` 객체가 생성된다고 볼 수는 없다.

# 2. type()과 id()

```python
x = 10

print(type(x))
print(id(x))
```

`type()`은 객체의 자료형을 확인한다.

```python
print(type(x))
```

예:

```text
<class 'int'>
```

`id()`는 객체의 **고유한 identity 값**을 확인한다.

```python
print(id(x))
```

이후:

```python
x = "hello"

print(type(x))
print(id(x))
```

를 실행하면 `x`가 문자열 객체를 새롭게 가리킨다.

## 주의

```text
id() = 메모리 주소
```

라고 완전히 동일하게 외우는 것은 정확하지 않다.

CPython에서는 메모리 주소와 관련된 값으로 구현되는 경우가 많지만, Python 언어 자체에서는 **객체의 고유 identity**라고 이해하는 것이 정확하다.

# 3. Garbage Collector

Python은 일반적으로 개발자가 직접 메모리 해제를 관리하지 않아도 된다.

예:

```python
x = 10
x = "hello"
```

`x`가 더 이상 `10`을 가리키지 않게 되고, 다른 곳에서도 해당 객체를 사용하지 않는다면 Python의 메모리 관리 시스템이 필요에 따라 정리한다.

```text
객체 생성
   ↓
변수가 객체 참조
   ↓
더 이상 참조하지 않음
   ↓
Python이 메모리 관리
```

즉:

```text
개발자가 직접 메모리 해제를 일일이 처리할 필요가 적다.
```

# 6. GitHub Repository 생성

Private Repository 생성:

```bash
gh repo create kant_python --private
```

`kant_python`이라는 Private Repository를 GitHub에 생성한다.

현재 로컬 Git 저장소까지 연결하고 싶다면:

```bash
gh repo create kant_python --private --source=. --remote=origin
```

현재 Commit까지 바로 Push하려면:

```bash
gh repo create kant_python --private --source=. --remote=origin --push
```

구조:

```text
--private
→ Private Repository

--source=.
→ 현재 폴더를 Source로 사용

--remote=origin
→ Remote 이름을 origin으로 등록

--push
→ 기존 Commit까지 Push
```

# 16. Short-Circuit Evaluation

Python의 `and`, `or`는 결과가 이미 결정되었다면 뒤쪽 표현식을 실행하지 않을 수 있다.

## and

```python
print(False and (10 / 0 > 1))
```

앞의 `False`만으로 전체 결과가 `False`라고 결정된다.

따라서:

```python
10 / 0
```

을 실행하지 않는다.

결과:

```text
False
```

## or

하지만:

```python
print(False or (10 / 0 > 1))
```

에서는 앞이 `False`이므로 뒤의 결과를 확인해야 한다.

따라서:

```python
10 / 0
```

이 실행되어:

```text
ZeroDivisionError
```

가 발생한다.

# 17. 연산자 우선순위

대표적인 우선순위는 다음과 같이 이해하면 된다.

```text
()
↓
**
↓
*  /  //  %
↓
+  -
↓
비교 연산자
↓
not
↓
and
↓
or
```

괄호가 가장 우선한다.

예:

```python
result = 10 + 2 * 5 > 25
```

먼저:

```text
2 * 5 = 10
10 + 10 = 20
20 > 25
```

결과:

```text
False
```

반면:

```python
result = (10 + 2) * 5 > 25
```

먼저 괄호:

```text
10 + 2 = 12
12 * 5 = 60
60 > 25
```

결과:

```text
True
```

# 22. 주문 내역 출력 예제

```python
orders = [
    ("Latte", 5000, 2),
    ("Americano", 3000, 1),
    ("Cake", 6000, 1),
]

print("=" * 45)
print(f"{'메뉴명':<12}{'단가':>8}{'수량':>8}{'금액':>12}")
print("-" * 45)

total_amount = 0

for menu, price, qty in orders:
    subtotal = price * qty
    total_amount += subtotal

    print(
        f"{menu:<12}"
        f"{price:>8,}"
        f"{qty:>8}"
        f"{subtotal:>12,}"
    )

print("-" * 45)
print(f"{'합계금액:':<12}{total_amount:>28,}원")
```

`for`문으로 각각의 주문 데이터를 꺼낸다.

```python
for menu, price, qty in orders:
```

각 값은:

```text
menu  → 메뉴 이름
price → 가격
qty   → 수량
```

이다.

# 29. List와 Tuple 메모리 비교

```python
import sys

print(sys.getsizeof([1, 2, 3]))
print(sys.getsizeof((1, 2, 3)))
```

같은 형태의 단순 데이터에서는 Tuple이 List보다 작은 크기로 나타나는 경우가 있다.

하지만:

```python
sys.getsizeof()
```

는 객체 자체의 **얕은 크기(shallow size)** 를 보여준다.

내부 객체 전체의 실제 메모리 사용량을 모두 계산하는 것은 아니다.

Tuple의 가장 중요한 특징은 메모리 크기보다는:

```text
생성 후 요소를 변경할 수 없다.
```

는 점이다.
