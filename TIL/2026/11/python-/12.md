## 1. Docker 핵심 개념

Docker는 애플리케이션 실행에 필요한 환경을 컨테이너로 구성하고 실행하는 플랫폼이다.

### 이미지와 컨테이너

| 구분 | 이미지(Image) | 컨테이너(Container) |
|---|---|---|
| 개념 | 실행 환경의 원본 | 이미지로 생성한 실행 환경 |
| 생성 | `docker pull` | `docker run` |
| 실행 | 직접 실행되지 않음 | 실행 및 중지 가능 |
| 삭제 | `docker rmi` | `docker rm` |
| 특징 | 하나의 이미지로 여러 컨테이너 생성 가능 | 각각 독립된 환경을 가짐 |

### Docker 작동 구조

```text
사용자
  ↓
Docker Client
  ↓
Docker Engine (Daemon)
  ↓
이미지 다운로드 및 컨테이너 관리
  ↓
컨테이너 실행
```

- **Docker Client**: 사용자가 입력한 명령어를 Docker Engine에 전달
- **Docker Engine**: 이미지 및 컨테이너를 관리하고 실행
- **Docker Hub**: Docker 이미지를 다운로드할 수 있는 저장소

## 2. Docker 기본 명령어

| 명령어 | 기능 |
|---|---|
| `docker --version` | Docker 버전 확인 |
| `docker info` | Docker 클라이언트 및 서버 정보 확인 |
| `docker context ls` | Docker 연결 환경 확인 |
| `docker pull ubuntu:24.04` | 이미지 다운로드 |
| `docker images` | 이미지 목록 확인 |
| `docker image ls` | 이미지 목록 확인 |
| `docker ps` | 실행 중인 컨테이너 조회 |
| `docker ps -a` | 모든 컨테이너 조회 |
| `docker ps -al` | 가장 최근 생성된 컨테이너 조회 |
| `docker rmi 이미지ID` | 이미지 삭제 |

### 이미지 이름과 태그

```bash
docker pull ubuntu:24.04
```

- `ubuntu`: 이미지 이름
- `24.04`: 이미지 버전(태그)
- `:`: 이미지 이름과 버전을 구분

버전을 지정하지 않으면 기본적으로 `latest` 태그가 사용된다.

## 3. 컨테이너 생성 및 실행

### Ubuntu 컨테이너 실행

```bash
docker run -it --name my-server ubuntu:24.04 bash
```

| 문법 | 기능 |
|---|---|
| `docker run` | 새 컨테이너 생성 및 실행 |
| `-i` | 표준 입력 유지 |
| `-t` | 터미널 할당 |
| `--name my-server` | 컨테이너 이름 지정 |
| `ubuntu:24.04` | 사용할 이미지 |
| `bash` | 컨테이너 내부에서 Bash 실행 |

### run / start / exec 차이

| 명령어 | 기능 |
|---|---|
| `docker run` | 새로운 컨테이너 생성 및 실행 |
| `docker start` | 기존 컨테이너 시작 |
| `docker exec` | 실행 중인 컨테이너 내부에서 명령어 실행 |

**컨테이너 재시작 및 접속**

```bash
docker start -ai my-server
```

중지된 컨테이너를 시작하고 기존 프로세스에 연결한다.

```bash
docker exec -it my-server bash
```

실행 중인 컨테이너에서 새로운 Bash 세션을 실행한다.

### 주요 옵션

| 옵션 | 설명 |
|---|---|
| `-it` | 터미널에서 대화형 실행 |
| `-d` | 백그라운드 실행 |
| `--name` | 컨테이너 이름 지정 |
| `-p` | 호스트와 컨테이너 포트 연결 |
| `-e` | 환경변수 설정 |
| `-a` | 명령어에 따라 전체 조회 또는 출력 연결 |

## 4. 컨테이너 생명주기 관리

```text
이미지 다운로드 (pull)
        ↓
컨테이너 생성 및 실행 (run)
        ↓
실행 중 (Up)
        ↓
컨테이너 중지 (stop)
        ↓
종료 상태 (Exited)
        ↓
재시작 (start) 또는 삭제 (rm)
```

### 컨테이너 관리 명령어

| 명령어 | 기능 |
|---|---|
| `docker stop my-server` | 컨테이너 중지 |
| `docker start my-server` | 컨테이너 시작 |
| `docker restart my-server` | 컨테이너 재시작 |
| `docker rm my-server` | 중지된 컨테이너 삭제 |
| `docker rmi ubuntu:24.04` | 이미지 삭제 |

### 컨테이너와 이미지 삭제

```bash
docker stop my-server
docker rm my-server
docker rmi ubuntu:24.04 
```

**기억할 점**

- `stop`은 실행 중인 컨테이너를 중지한다.
- `rm`은 컨테이너를 삭제한다.
- `rmi`는 이미지를 삭제한다.
- 컨테이너를 중지해도 내부 데이터는 유지된다.
- 컨테이너 삭제 시 내부에만 저장한 데이터는 일반적으로 사라진다.
- 데이터를 별도로 보존하려면 Docker Volume 또는 Bind Mount가 필요하다.

## 5. Ubuntu 컨테이너 및 Linux 명령어

Ubuntu 컨테이너에서 Linux 명령어를 실행했다.

| 명령어 | 기능 |
|---|---|
| `whoami` | 현재 사용자 확인 |
| `pwd` | 현재 디렉터리 경로 확인 |
| `ls` | 파일 및 디렉터리 목록 |
| `ls -al` | 숨김 파일 포함 상세 목록 |
| `cd /etc` | 지정된 경로로 이동 |
| `cd ..` | 상위 디렉터리 이동 |
| `cat 파일명` | 파일 내용 출력 |
| `echo "내용"` | 텍스트 출력 |
| `exit` | 현재 셸 종료 |

### 파일 생성 및 확인

```bash
echo "# Hello Docker" > README.md
```

```bash
cat README.md
```

| 문법 | 의미 |
|---|---|
| `echo` | 문자열 출력 |
| `>` | 출력 결과를 파일에 저장하거나 기존 내용 덮어쓰기 |
| `cat` | 파일 내용 확인 |

컨테이너 내부에서 생성한 파일은 같은 컨테이너를 중지하고 재시작해도 유지되는 것을 학습했다.

## 6. Nginx 웹 서버 실행

Nginx는 HTTP 요청을 받아 웹 페이지를 제공하는 웹 서버이다.

### Nginx 컨테이너 생성

```bash
docker run -d --name my-webserver -p 8080:80 nginx
```

| 문법 | 의미 |
|---|---|
| `-d` | 백그라운드 실행 |
| `--name my-webserver` | 컨테이너 이름 지정 |
| `-p 8080:80` | 호스트 8080번 포트를 컨테이너 80번 포트에 연결 |
| `nginx` | Nginx 이미지 |

### 포트 연결 구조

```text
Windows (localhost:8080)
          ↓
     Docker 포트 연결
          ↓
Nginx 컨테이너 (80번 포트)
          ↓
       HTML 응답
```

### 웹 서버 응답 확인

```bash
curl localhost:8080
```

Nginx 기본 HTML 페이지가 정상적으로 반환되는 것을 확인했다.

### HTML 파일 수정

```bash
docker exec -it my-webserver bash
```

```bash
cd /usr/share/nginx/html
cat index.html
```

```bash
echo '<h1>Hello Docker</h1>' > index.html
```

컨테이너 내부의 `index.html`을 수정하여 웹 페이지에 표시되는 내용을 변경했다.

## 7. MySQL 컨테이너 실행

### MySQL 이미지 다운로드

```bash
docker pull mysql:8.4
```

### 컨테이너 생성

```bash
docker run -d --name my-sql -e MYSQL_ROOT_PASSWORD=admin1234 -p 3306:3306 mysql:8.4
```

| 문법 | 의미 |
|---|---|
| `--name my-sql` | 컨테이너 이름 |
| `-e` | 환경변수 지정 |
| `MYSQL_ROOT_PASSWORD` | 초기 관리자 비밀번호 |
| `-p 3306:3306` | MySQL 포트 연결 |
| `mysql:8.4` | MySQL 이미지 버전 |

### MySQL 접속

```bash
docker exec -it my-sql mysql -uroot -p
```

- `-uroot`: root 사용자로 접속
- `-p`: 비밀번호 입력 요청

데이터베이스 목록 확인:

```sql
SHOW DATABASES;
```

종료:

```sql
EXIT;
```

## 8. PostgreSQL 컨테이너 실행

### PostgreSQL 이미지 다운로드

```bash
docker pull postgres:18
```

### 컨테이너 생성

```bash
docker run -d --name my-pg -e POSTGRES_PASSWORD=admin -p 5432:5432 postgres:18
```

### PostgreSQL 접속

```bash
docker exec -it my-pg psql -U postgres
```

| 명령어 | 기능 |
|---|---|
| `\l` | 데이터베이스 목록 확인 |
| `\dt` | 현재 데이터베이스의 테이블 목록 확인 |
| `\q` | PostgreSQL 종료 |

### MySQL과 PostgreSQL 비교

| 구분 | MySQL | PostgreSQL |
|---|---|---|
| 이미지 | `mysql:8.4` | `postgres:18` |
| 포트 | 3306 | 5432 |
| 접속 프로그램 | `mysql` | `psql` |
| DB 목록 | `SHOW DATABASES;` | `\l` |
| 종료 | `EXIT;` | `\q` |

두 데이터베이스 모두 Docker 컨테이너를 통해 별도의 로컬 설치 과정 없이 실행할 수 있다.

## 9. 로그 및 네트워크 확인

### Docker 로그 확인

```bash
docker logs my-webserver
```

컨테이너에서 출력된 로그를 확인한다.

```bash
docker logs -f my-webserver
```

새롭게 출력되는 로그를 실시간으로 확인한다.

### 네트워크 확인

```bash
curl localhost:8080
```

HTTP 요청을 보내 웹 서버 응답을 확인한다.

```bash
netstat -ano | grep :8080
```

Windows에서 8080번 포트를 사용하는 네트워크 연결 및 프로세스 ID를 확인한다.

| 문법 | 기능 |
|---|---|
| `netstat -ano` | 네트워크 연결 및 PID 확인 |
| `\|` | 앞 명령어 결과를 뒤 명령어로 전달 |
| `grep :8080` | 8080 포트가 포함된 줄 검색 |

## 10. 오류 및 수정 사항

| 오류 | 원인 | 해결 |
|---|---|---|
| Docker API 연결 실패 | Docker Engine 미실행 또는 연결 실패 | Docker Desktop 실행 및 연결 확인 |
| `No such image` | 잘못된 이미지 ID | `docker images`로 확인 |
| `No such container` | 잘못된 컨테이너 ID | `docker ps -a`로 확인 |
| `image is being used` | 컨테이너에서 이미지 사용 중 | 컨테이너 중지·삭제 후 이미지 삭제 |
| `docker start -al` | 알파벳 `l`과 `i` 혼동 | `docker start -ai` |
| `--namer` | 옵션 이름 오타 | `--name` |
| `pull access denied` | 이미지 이름 오류 또는 접근 권한 부족 | 올바른 이미지 이름과 옵션 확인 |
| `container name already in use` | 같은 이름의 컨테이너 존재 | 기존 컨테이너 재사용 또는 삭제 |
| `lsof: command not found` | Git Bash에 명령어 없음 | `netstat -ano` 활용 |
| `event not found` | Bash에서 `!`를 히스토리 확장으로 처리 | 작은따옴표 사용 |
| `docker ps-a` | 공백 누락 | `docker ps -a` |
| PostgreSQL `/q` | 종료 명령어 오타 | `\q` 사용 |
