# 2. Branch

Branch는 기존 `main` 작업을 유지하면서 새로운 기능을 따로 개발할 수 있게 해준다.

예:

```text
main
  |
  A
  |
  B
   \
    C ← feature/login
```

## Branch 생성

```bash
git branch feature/login
```

Branch만 생성하고 현재 위치는 그대로다.

확인:

```bash
git branch
```

예:

```text
  feature/login
* main
```

`*`가 현재 위치한 Branch다.

---

# 3. Branch 이동

```bash
git checkout feature/login
```

또는 최근에는:

```bash
git switch feature/login
```

을 사용할 수 있다.

---

# 4. Branch 생성 + 이동

한 번에 생성하고 이동:

```bash
git checkout -b feature/login
```

또는:

```bash
git switch -c feature/login
```

즉:

```text
git branch
→ Branch 생성

git checkout / git switch
→ Branch 이동

git checkout -b / git switch -c
→ Branch 생성 + 바로 이동
```

# 5. Commit 기록 확인

간단하게 Commit 확인:

```bash
git log --oneline
```

모든 Branch의 Commit 확인:

```bash
git log --oneline --all
```

Branch가 어떻게 갈라졌는지 그래프로 확인:

```bash
git log --oneline --all --graph
```

Branch 이름까지 보기 쉽게 확인하려면:

```bash
git log --oneline --all --graph --decorate
```

예:

```text
* 34abc12 (feature/login) feat: 로그인 추가
| * 91abc25 (main) docs: README 수정
|/
* a12bc34 initial commit
```

# 6. Merge

다른 Branch의 작업을 **현재 Branch에 병합**한다.

예를 들어:

```text
main
 |
 A ─ B
      \
       C ─ D
           ↑
     feature/login
```

`feature/login`을 `main`에 합치고 싶다면 먼저:

```bash
git switch main
```

그다음:

```bash
git merge feature/login
```

즉:

```text
현재 위치: main

git merge feature/login

feature/login
      ↓
     main에 병합
```

## 핵심

```bash
git merge 브랜치명
```

은:

> 지정한 Branch를 현재 내가 있는 Branch에 합친다.

# 7. Merge Conflict

두 Branch에서 **같은 파일의 같은 부분을 서로 다르게 수정**하면 Git이 어떤 내용을 선택해야 하는지 판단하지 못할 수 있다.

이것을:

```text
Merge Conflict
```

라고 한다.

예:

```text
main
→ 로그인 버튼

feature/login
→ 회원 로그인 버튼
```

같은 부분을 서로 다르게 수정했다면 Conflict가 발생할 수 있다.

---

# 8. Conflict 해결

충돌이 발생하면 VS Code에서 충돌한 부분을 확인한다.

방법 1:

```text
직접 필요 없는 내용을 삭제하고
원하는 최종 코드로 수정
```

방법 2:

VS Code의 Merge Editor 등을 사용해 양쪽 내용을 비교하면서 수정한다.

수정량이 많거나 복잡할 때 비교 화면을 사용하면 편하다.

충돌을 해결한 후:

```bash
git add .
```

그리고 Merge Commit이 필요한 상황이라면:

```bash
git commit -m "merge: resolve conflict"
```

마지막으로:

```bash
git push
```

# 9. Vim 기본 조작

Git 작업 중 Commit 메시지를 입력할 때 Vim이 열릴 수 있다.

입력 모드:

```text
i
```

현재 줄 맨 끝에서 입력:

```text
Shift + A
```

일반 모드로 돌아가기:

```text
Esc
```

명령어 입력을 시작하려면:

```text
:
```

저장하고 종료:

```vim
:wq
```

저장하지 않고 종료:

```vim
:q!
```

## 위치 이동

파일 맨 아래:

```text
G
```

파일 맨 위:

```text
gg
```

따라서:

```text
Shift + A
→ 맨 위 이동 ❌
→ 현재 줄 끝에서 입력 시작 ✅

Shift + :
→ 맨 아래 이동 ❌
→ : 명령 입력 시작 ✅
```

# 11. 기본 협업 흐름

내 작업:

```bash
git add .
git commit -m "feat: 작업 내용"
git push
```

그런데 다른 팀원이 먼저 Push해서 GitHub가 더 최신이라면 내 Push가 거절될 수 있다.

이럴 때:

```bash
git pull
```

로 원격 변경사항을 먼저 가져온다.

문제가 없다면:

```bash
git push
```

---

# 12. 같은 파일을 수정한 경우

예를 들어:

```text
나
→ login.js 수정

팀원
→ login.js의 같은 부분 수정
```

팀원이 먼저 Push했다면 내가:

```bash
git pull
```

했을 때 Conflict가 발생할 수 있다.

그 경우:

```text
1. 충돌 부분 확인
2. 사용할 코드 결정
3. 파일 수정
4. git add
5. commit
6. push
```

순서로 처리한다.

예:

```bash
git add .
git comm it -m "merge: resolve login conflict"
git push
```

# 13. 오늘의 핵심 흐름

Branch 작업:

```text
main
↓
새 Branch 생성
↓
Branch 이동
↓
기능 개발
↓
Commit
↓
main 이동
↓
Merge
```

명령어로 보면:

```bash
git switch -c feature/login

# 작업

git add .
git commit -m "feat: add login"

git switch main
git merge feature/login
```

협업은:

```text
내 작업
↓
commit
↓
다른 사람이 먼저 push했는지 확인
↓
필요하면 pull
↓
Conflict 발생 시 해결
↓
push
```
